## Service protocol verification

A fake `launchctl` (PID state file) plus a local HTTP server returning Prometheus text (`ccr_active_requests 0`) on `/metrics` and `200` on `/health` was used to exercise the full restart path. The parser initially accepted only JSON; review against the live endpoint showed CCR returns Prometheus text, and the parser was corrected before publication:

```
restarted demo: pid 0 -> 101, idle wait 0.0s, health true
```

Events recorded `claim.acquired` (service + port), `service.restart`, and `lease.released`. This proves the protocol wiring, not real launchd behavior.
