# Agent context propagation, 2026-10-23

## Objective

Make the Arbiter knowledge available to every local coding harness that reads
the machine instruction stack or the shared memory store, not only to the
Arbiter repo, toolbelt catalog, and the Qoder project memory.

The canonical section states: wrap sessions with `arbiter run --auto`, preflight
with `arbiter check` and `arbiter scan --check`, use `arbiter git` for guarded
git, use `ccr-worker-lease` and `ccr-service-restart` for CCR, and treat claims
as advisory outside those boundaries. It also records the architectural split:
ccr-rust owns model routing and admission; Arbiter owns machine resources.

## Non-claims and limits

- Global instruction files are loaded at session start. Running Codex, ZCode,
  Claude, Qoder, Gemini, Kimi, or OpenCode sessions do not retroactively reload
  them; the new knowledge reaches new sessions and any session that explicitly
  re-reads the files or memory.
- Kimi's compact section is manual, not generated by `agent-instructions-sync`,
  so it can drift from the canonical section.
- OpenCode's global path is a best-effort pointer; its loader behavior was not
  empirically verified. Harnesses that only read project-local `AGENTS.md` will
  see the section when working in a repository that includes it.
- The shared memory leaf is the discovery fallback for any harness that runs
  `memsearch` or reads the memory-sync index.
